# 专题 04：栈与队列

> 核心思想：栈是后进先出（LIFO），队列是先进先出（FIFO）。单调栈是大数据场景的利器。

## 适用场景

- **栈**：嵌套结构匹配（括号、HTML 标签）、表达式求值、回溯（DFS 隐式栈）
- **队列**：层序遍历（BFS）、任务调度、滑动窗口
- **单调栈**：找下一个更大/更小元素（时序数据、股票价格）

## 三道经典题

---

### 题 1：有效的括号（Valid Parentheses）

**题目**：判断括号字符串是否合法。`"()[]{}"` → true，`"([)]"` → false

**思路**：用栈匹配：
- 遇到左括号，压栈
- 遇到右括号，检查栈顶是否是对应的左括号
- 最终栈为空说明全部匹配

**复杂度**：时间 O(n)，空间 O(n)

**面试追问**：
- "如果只有一种括号？" → 计数即可，不需要栈
- "如果是 HTML 标签匹配？" → 栈存标签名，遇到闭合标签检查栈顶

**破坏练习**：输入 `"(]"` 或 `"([)]"`，观察在哪一步失败

---

### 题 2：最小栈（Min Stack）

**题目**：设计一个栈，支持 push/pop/top/getMin，所有操作 O(1)。

**思路**：双栈法：
- 主栈存所有元素
- 辅助栈存"当前最小值"（每次 push 时，辅助栈压入 min(新元素, 辅助栈栈顶)）

**复杂度**：时间 O(1) 各操作，空间 O(n)

**面试追问**：
- "能不能只用一个栈？" → 可以，栈里存差值（当前元素 - 最小值），但需要小心溢出
- "如果是队列而不是栈？" → 单调队列（滑动窗口最大值）

**破坏练习**：连续 push 相同元素，观察 getMin 行为

---

### 题 3：每日温度（Daily Temperatures）—— 单调栈经典

**题目**：给定温度数组，返回每个温度要等多少天才能遇到更高温度。`[73, 74, 75, 71, 69, 72, 76, 73]` → `[1, 1, 4, 2, 1, 1, 0, 0]`

**思路**：单调递减栈（栈底到栈顶递减）：
- 遍历温度，如果当前温度 > 栈顶温度，说明栈顶找到了"下一个更高"
- 弹出栈顶，计算天数差，继续比较
- 当前温度入栈

**复杂度**：时间 O(n)（每个元素最多入栈出栈各一次），空间 O(n)

**面试追问**：
- "如果是找下一个更低的温度？" → 单调递增栈
- "如果是循环数组（最后一天后回到第一天）？" → 遍历两遍或用取模

**破坏练习**：输入单调递减序列，观察结果全为 0

## 栈的本质

栈的核心是**后进先出**，所有题目都是这个性质的变体：
- 括号匹配：后进的左括号必须先匹配
- 最小栈：辅助栈记录"历史最小"，后进的先出
- 单调栈：维护单调性，后进的元素可能先出（破坏单调性时）

面试时先说"为什么用栈"，再讲具体操作。

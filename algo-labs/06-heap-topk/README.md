# 专题 06：堆与 TopK

> 核心思想：堆是优先队列的实现，能在 O(log n) 时间内维护最值。TopK 问题是大数据处理的核心。

## 适用场景

- **TopK 问题**：找最大/最小的 K 个元素（推荐系统、排行榜）
- **多路归并**：合并 K 个有序序列（外部排序、多文件合并）
- **实时统计**：维护中位数、最值（数据流处理）

## 三道经典题

---

### 题 1：数组中的第 K 个最大元素（Kth Largest Element）

**题目**：找数组中第 K 大的元素（不是第 K 个不同元素）。

**思路**：
- **方法 1：最小堆**（适合 TopK）- 维护大小为 K 的最小堆，遍历数组，堆顶就是第 K 大。时间 O(n log k)，空间 O(k)
- **方法 2：快速选择**（平均 O(n)）- 类似快排 partition，每次只递归一侧

**复杂度**：堆方法 O(n log k)，快选平均 O(n) 最坏 O(n²)

**面试追问**：
- "如果数据是流式的（一次来一个）？" → 用堆，维护 K 个最大
- "如果 K 接近 n？" → 快选更好，堆的 log k 接近 log n

**破坏练习**：数组有重复元素，观察两种方法的行为

---

### 题 2：合并 K 个升序链表（Merge K Sorted Lists）

**题目**：合并 K 个升序链表为一个升序链表。

**思路**：最小堆（优先队列）：
- 把 K 个链表的头节点放入堆
- 每次取出堆顶（最小），接到结果链表，把该链表的下一个节点入堆
- 直到堆空

**复杂度**：时间 O(N log k)（N 是总节点数，k 是链表数），空间 O(k)（堆大小）

**面试追问**：
- "分治法（两两合并）？" → 时间 O(N log k)，但实现更复杂
- "如果 K 很大（如 10 万）？" → 分治法更好，避免堆过大

**破坏练习**：某个链表为空，观察是否能正确处理

---

### 题 3：数据流的中位数（Find Median from Data Stream）

**题目**：设计数据结构，支持 addNum 和 findMedian，要求高效。

**思路**：两个堆：
- **大顶堆**（left）：存较小的一半，堆顶是左半部分的最大值
- **小顶堆**（right）：存较大的一半，堆顶是右半部分的最小值
- 保持平衡：left.size() == right.size() 或 left.size() == right.size() + 1
- 中位数：奇数取 left 堆顶，偶数取 (left.top + right.top) / 2

**复杂度**：addNum O(log n)，findMedian O(1)

**面试追问**：
- "如果 99% 的数在 0-100 之间？" → 用计数数组（101 个桶），addNum O(1)，findMedian O(100)
- "如果数据量极大（10 亿）？" → 近似算法（T-Digest、DDSketch）

**破坏练习**：连续添加相同数字，观察两个堆的平衡

## 堆的本质

堆的核心是**优先队列**：
- **最小堆**：堆顶是最小值（PriorityQueue 默认）
- **最大堆**：堆顶是最大值（用 Comparator.reverseOrder() 或 -value）

所有堆题目都是：
1. 确定维护什么（最大 K 个？最小值？）
2. 选择堆类型（最小堆 or 最大堆）
3. 控制堆大小（K 或平衡）

面试时先说"用什么堆、维护什么、怎么平衡"，再写代码。

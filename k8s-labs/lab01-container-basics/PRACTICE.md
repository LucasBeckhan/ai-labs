## 第一轮：手写（30–45 分钟）

从空白写 Dockerfile：JDK 编译、JRE 运行、普通用户、ENTRYPOINT；构建 hello:practice。禁止复制现有 Dockerfile。

在本章创建自己的 `work/` 目录；不要覆盖参考文件。先口述每个字段的作用，再写 YAML。允许查 `kubectl explain` 和官方 API 文档，不允许整段复制答案。应用前执行 `kubectl --context kind-labs apply --dry-run=server -f work/`（Dockerfile 不适用）；dry-run 仅验证 API 可接受，不证明程序可运行。

产出：Dockerfile.practice；分别用 256MiB、512MiB 启动的输出；docker history 输出。

## 第二轮：故障注入与恢复（30–45 分钟）

故障 A：把 ENTRYPOINT 的主类写成 Missing，构建能成功但运行失败。故障 B：执行 docker run --rm --memory=512m --entrypoint java hello:practice -Xmx64m Hello，对比默认堆。

每次先保存健康基线，写下预期，再注入一个故障；按 [排障记录模板](../INCIDENT-TEMPLATE.md) 保存证据。只修改自己的练习对象。涉及节点污点或限额时，先记录原值，结束恢复原值。

验收：A：日志包含类加载失败，退出码非零；修复类名后正常退出。B：堆约 64MiB，容器上限仍为 512MiB。不要靠盲目增加内存修复。

## 第三轮：面试复述（5 分钟）

# Lab09：安全运营周报 Workflow

> 约6小时。前置 Lab02/04/07；关联用户现有“云安全周报”工作。以下字段与数据均为教学假设，不代表公司现有周报接口、指标定义或客户约定。主线固定，模型只参与说明文字。

## 业务任务

输入：已认证租户、周起止时间、时区、报表模板版本。
输出：待审核报告，包含数据覆盖范围、原始条数、去重告警数、严重性分布、证据引用、数据缺口。报告默认不对外发送。

```text
校验身份/时间窗 → 获取事件 → 去重与质量检查 → 确定性聚合
                                               ↓
                         检索有效说明 → 模型撰写解读草稿
                                               ↓
                         核对数值与引用 → 人工审核 → 模拟归档
```

## 第一步：独立写数据口径（45分钟）

在 work/metric-contract.md 写清以下定义，再编码：

- 时间使用带时区ISO8601；将业务自然周转为UTC半开区间[start,end)，保留原时区和起止时间。
- 去重键为tenant_id+event_id；同一事件不同版本如何选取必须明确，不可默认最后到达就是最新。现有fixture仅用来验证相同ID去重数。
- 缺失severity记unknown，不悄悄丢弃；列表接口未拉完分页、数据源失败都应标partial，不能解释成零事件。
- 告警总量不等于攻击次数，不足以证明成功入侵；不从几条告警推断SLA达标。
- 迟到事件是否补报、report_version如何递增需有规则；同一周不同版本不覆盖审计记录。

## 第二步：写确定性基线（90分钟）

先从agent-labs运行：

```bash
python3 business/sandbox.py --scenario report
```

示例短窗口为2026-10-28 00:00Z至02:00Z；预期raw_count=3、unique_count=2，ID为E-001、E-002。这不是完整周数据，只用来练窗口与去重。

然后写 work/report_workflow.py，读取fixture，扩展一整周数据：至少20条（含重复、迟到、unknown、其他租户、左/右边界）。自己写预期聚合，再实现过滤、去重、分组、coverage。报告结构中 facts 数字只能来自聚合器。

手写函数：normalize_window、fetch_pages、deduplicate、aggregate、build_draft、validate_report。聚合单元测试全部通过后，才调用LLM写解读；模型适配层可用FakeModel返回预设JSON测试。

## 第三步：RAG解读与核对（60分钟）

模型只能引用facts中的metric_id，不能自己生成数值字段。比如“高危告警增加”需要两个可比周的数据与相同口径，缺上周就不写增长率；除数为0明确标记not_comparable。模型输出的动作建议标为建议，不能变成已执行事件。

自动校验引用ID存在、数值一致、模板必填项齐全；不通过最多重写一次，然后needs_review。知识库仅提供说明，不覆盖真实聚合结果。

## 第四步：生产故障（90分钟）

| 注入 | 期望行为 | 验收 |
|---|---|---|
| API第二页timeout | partial，不发布完整报告 | coverage缺口和错误码保留 |
| 重复投递E-001 | unique_count不增加 | 重复条数有记录 |
| 右边界事件 | 留到下一窗口 | 不双算也不漏掉下一期 |
| 模型凭空增加“攻击20次” | 校验失败/待审核 | 不把输出直接归档 |
| 手册包含“忽略权限” | 当资料处理 | 不能改变工具权限 |
| 同一周重复运行 | 同版本可复用，改变输入需新版本 | report_key与输入hash一致 |

## 第五步：接近实际接口的练习

定义CloudSecurityAdapter接口，不填真实厂商域名或凭据。先写分页、超时、429、权限拒绝的Fake Adapter，再根据正式接口文档接入。需要交付字段映射、鉴权方法、错误分类、数据新鲜度、限流预算。未经公司授权不接真实客户数据。

## 验收与面试

交付完整周fixture、指标口径、6类故障测试、Markdown报告和机器可读facts。数字100%一致，partial不得写成完整周报。比较固定Workflow与自由Agent：本场景原则上先用Workflow，只有知识检索/解释步骤需要模型。

追问：为何不用LLM直接统计？接口失败与真实零事件如何区别？迟到数据如何重算不重复发布？怎样与DolphinScheduler对接定时调度？

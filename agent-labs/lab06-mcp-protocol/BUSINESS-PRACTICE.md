# 把企业只读工具开放为 MCP 接口

> 建议 4小时，完成后提交自己的实现和证据。所有业务数据为虚构；原 README/脚本提供机制参考，本页是新增业务必做练习。新版总入口：[业务路线](../CURRICULUM.md)。

## 业务输入与完成边界

让不同 AI 客户端复用链路/告警/手册工具；协议统一不代表任意客户端都能读取所有客户数据。

先回答：谁发起？要解决什么问题？允许读什么？哪些动作要人工确认？缺数据如何结束？这五项写入 work/README.md 后再编码。

## 从空白手写的任务

1. 先运行原 mini_mcp.py 观察 JSON-RPC 帧，标注它固定使用 2024-11-05、仅教学子集，不将旧握手和 stdio 机制泛化到所有版本/传输。
2. 创建 work/pyproject.toml，选定并锁定 SDK/协议版本，使用该版本官方文档实现 list/call；把版本、传输、能力及错误规则写进 README。新版本与旧版本需按所选规范处理，不照抄旧 demo 假装兼容。
3. 仅暴露 business 中3个只读工具，错误用结构化业务码；工具失败与 JSON-RPC 协议错误分别验证。tools/list 只列出当前可用工具，但 tools/call 仍要重新授权。
4. stdio 日志只走 stderr；测试 stdout 每行可解析为协议消息。HTTP 版本需校验认证/受众/权限和传输要求，不能把任意 token 透传到下游。
5. 从服务端可信身份构造 Context，拒绝客户端参数覆盖 tenant；增加“有 tools/list 但无权调用”“未知工具”“参数错误”“取消/依赖超时”测试。
6. 不暴露原计算器 eval、密码生成器或任意 shell/SQL/URL 工具；对生产连接需要另行完成接口、凭据和授权评审。

## 运行入口与参考边界

旧演示使用其原 Python 环境执行 `python mini_mcp.py --test`。新业务 MCP 是手写任务，SDK 未安装时不能报告已通过；离线阶段仅运行 business/tests 的直接调用契约。

模型阶段不限定框架。优先沿用原有模型网关适配器，但密钥从环境/Secret获取，不复用旧例子中的硬编码演示值。离线FakeModel验证控制逻辑，真实模型验证工具选择和回答质量，两者分别报告。

## 故障与验收

同一工具经直接调用和 MCP 返回一致的租户过滤结果；协议版本有记录；错误不变成伪成功；日志不含凭据与客户正文。SDK 兼容性用锁定版本实测记录证明。

每个故障保存：输入、身份、关键trace、错误码、根因、最小修复、恢复结果、预防措施。对照 [生产故障表](../business/FAILURE-DRILLS.md)，不要把单纯重跑成功当修复。

# 网络与安全知识助手：证据、版本与权限

> 建议 5小时，完成后提交自己的实现和证据。所有业务数据为虚构；原 README/脚本提供机制参考，本页是新增业务必做练习。新版总入口：[业务路线](../CURRICULUM.md)。

## 业务输入与完成边界

工程师问“丢包怎么排查？”以及“客户合同规定多久恢复？”前者可以参考有效手册，后者在本训练数据中没有合同，不允许生成承诺。

先回答：谁发起？要解决什么问题？允许读什么？哪些动作要人工确认？缺数据如何结束？这五项写入 work/README.md 后再编码。

## 从空白手写的任务

1. 创建知识索引 schema：doc_id/chunk_id/tenant_id/acl/version/valid_from/valid_to/source_uri。先手写关键词 baseline，再接现有向量检索流程；ACL 过滤必须发生在文档进入模型之前。
2. 使用 KB-001（有效）、KB-002（失效）、KB-101（另一租户）构造检索测试。分别返回正确引用、空集、不泄露私有标题/正文。
3. 输出答案要附 doc_id、version、chunk 或可定位引文；生成后再校验证据确实支持该句，不允许引用一个文档名就称有依据。
4. 建立12条问题集：4条可答、3条缺资料、2条版本冲突、2条跨租户、1条检索文本注入。合同/SLA 数据缺失时固定返回 evidence_missing；阈值低不能改成凭模型常识回答客户合同。
5. 比较固定 RAG 与 Agentic RAG：同一问题最多重写一次、重检索一次。记录检索命中、引用正确、拒答、模型调用数与时延。不能从一次 embedding 距离降低推断普遍准确率提高。
6. 用结构化检索读取“谁/何时/什么指标”，知识库只提供方法；不能用旧手册代替实时状态。

## 运行入口与参考边界

从本章运行 `python3 ../business/sandbox.py --scenario network` 查看 KB 引用基线；再为自己的索引和回答器编写12例评估。向量服务不可用时跑关键词基线，标记未验证向量检索。

模型阶段不限定框架。优先沿用原有模型网关适配器，但密钥从环境/Secret获取，不复用旧例子中的硬编码演示值。离线FakeModel验证控制逻辑，真实模型验证工具选择和回答质量，两者分别报告。

## 故障与验收

可答题引用有效手册；未知 SLA 不猜数值；检索到注入文本也不产生额外授权；跨租户返回为空且响应/日志不泄露正文。语义正确性要人工盲评，并保存标准答案。

每个故障保存：输入、身份、关键trace、错误码、根因、最小修复、恢复结果、预防措施。对照 [生产故障表](../business/FAILURE-DRILLS.md)，不要把单纯重跑成功当修复。

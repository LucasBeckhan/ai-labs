## 从空白手写的任务

1. 手写 POST /v1/runs、GET /v1/runs/{id}、POST /v1/runs/{id}/cancel。task放body，不放URL；tenant来自认证上下文。状态 queued/running/needs_review/succeeded/failed/cancelled，资源查询再次做租户隔离。
2. 同步接口仅用于短小只读任务；长任务交给worker，支持总deadline、工具timeout、并发上限、队列长度、取消与预算。调用方max_steps仅是请求值，服务端按账户策略裁剪。
3. 重试只读依赖有总预算，429按策略退避；队列满拒绝，不能无限排队。一个租户耗尽额度不影响其他租户；按用户、租户分别限流。连接池和线程池大小要与模型/工具容量匹配。
4. 指标使用正确Counter/Histogram：成功/失败/取消/超时、排队时间、模型与工具耗时、token usage、重试数；不要将request_id/客户名作为指标label。trace日志用request_id关联，并脱敏，不保存敏感prompt正文。
5. 写 Dockerfile 和 Deployment/Service/ConfigMap/Secret：非root、资源、startup/readiness/liveness；健康检查不以模型服务即时可用作为存活条件。使用port-forward验证，避免依赖kind未映射的30081端口。
6. 先单副本离线FakeModel；再做2副本、共享状态存储、worker重启、网关429、工具timeout、队列满、取消演练。记录哪些任务可恢复、哪些仅返回失败，不宣称自动exactly-once。
7. 可选接Token平台：模型适配层保留model/request_id/usage，缺用量返回unknown；本地预算估算与供应商最终账单区分。不得把缓存和重试调用漏计。

## 故障与验收

跨租户查run返回不可访问；无凭据401/403；压力超过上限返回受控错误；超时不返回成功；探针能运行；取消被worker观察后不再发新工具。提交压测并发与硬件、P95、错误率、预算、恢复证据。

每个故障保存：输入、身份、关键trace、错误码、根因、最小修复、恢复结果、预防措施。对照 [生产故障表](../business/FAILURE-DRILLS.md)，不要把单纯重跑成功当修复。
